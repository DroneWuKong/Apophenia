# Security policy

## Supported versions

Security fixes target the current `main` branch and the newest published release. Development APKs from old workflow runs are not supported.

## Reporting a vulnerability

Please report security or privacy vulnerabilities privately through [GitHub Security Advisories](https://github.com/DroneWuKong/Apophenia/security/advisories/new).

Include the affected version or commit, reproduction steps, impact, and the smallest useful diagnostic material. Please do not include real observation exports, precise coordinates, Health Connect records, Garmin identifiers, signing material, access tokens, or other personal data.

Examples of in-scope reports include:

- unintended export or disclosure of locally stored observations;
- permission bypasses or collection that occurs without the documented opt-in;
- insecure external-intent or file-sharing behavior;
- unsafe handling of Garmin messages or replay identifiers;
- dependencies with a practical exploit path in this app.

General bugs and feature requests belong in the public issue tracker after sensitive details are removed.

## Disclosure

Please allow maintainers reasonable time to reproduce, fix, and publish an update before public disclosure. Acknowledgement and remediation timing depend on severity and maintainer availability; no response-time guarantee is currently offered.

## Safety boundary

Apophenia is not a medical device and should not be relied on for diagnosis, treatment, emergency decisions, or personal safety monitoring. Statistical or sensor-output concerns that do not create a software security/privacy issue should be reported as ordinary bugs.
